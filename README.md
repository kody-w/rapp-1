# RAPP — the wire that carries agents

> The protocol is **RAPP**. Like C has C89/C99/C11, RAPP has spec revisions and one wire tag,
> `rapp/1` — but the name of the thing is just RAPP. This repository is its standard.

**One protocol for agents that keep a verifiable memory and talk over one wire.** Five primitives
— canonicalization, content addressing, identity, the frame, the egg — specified exactly enough
that independent implementations produce bytes each other can trust. This repository is the whole
thing: the normative standard, a stdlib-only reference implementation, a conformance suite, and a
book that teaches it end to end.

> Not a framework. A *protocol*, in the sense that HTTP, JSON, and git's object model are
> protocols. When RAPP is called "the AI medium," this is the medium.

## Quickstart (60 seconds)

```bash
git clone https://github.com/kody-w/rapp-1
cd rapp-1

python3 conformance.py     # V1–V28 — the spec exercised against its own claims
python3 realcheck.py       # the spec run against the REAL committed estate
python3 examples/01_hello_frame.py   # build and verify your first frame
python3 examples/04_grow_a_dimension.py   # grow an organism, weigh it, and deal its card
python3 examples/05_rappid_card.py   # reproduce and verify a physical wake card
```

`conformance.py` proves the reference implementation obeys the spec. `realcheck.py` clones the
real public repos of a live estate and runs RAPP against **32 actually-committed frames** — and
shows you the two halves of the whole argument at once: the canonicalizer reproduces every real
stored hash byte-for-byte, and the protocol refuses every legacy envelope as the drift it exists
to end.

## Build with it: the SDK Builder agent

Drop one file into any RAPP brainstem's `agents/` directory (no restart) and it gains a working
RAPP toolkit — mint compliant rappids, scaffold organism seeds, build/verify frames,
content-address values, and lint public repos for compliance, all drivable in plain English:

```bash
curl -sSL https://raw.githubusercontent.com/kody-w/rapp-1/main/agents/rapp_sdk_builder_agent.py \
  -o ~/.brainstem/src/rapp_brainstem/agents/rapp_sdk_builder_agent.py
# then just talk to your brainstem: "scaffold a new RAPP organism @me/scratch"
```

It's self-contained (embeds the reference primitives; its `sync` action proves byte-identical
addresses to the public `rapp.py`) and falls back to a standalone base so it also runs outside a
brainstem: `python3 agents/rapp_sdk_builder_agent.py`.

## The one idea

The RAPP ecosystem is real and it drifted: the same concept — "a frame," "a rappid" — got built
more than once, in incompatible ways, each copy claiming the same name. A frame was minted twice
under one version string with two different hash rules; an identity was computed three ways in
production, one of them the cardinal sin of hashing a *name* into an address. This is the oldest
failure in distributed systems, and it was solved before — by Linux's one mainline, the Web's
single living standard, git making the hash the name. **RAPP is the convergence: one spec, one
canonicalizer, one mint, one frame** — specified so completely that the drift cannot come back,
because everyone building on it turns the same bytes into the same tree.

## Calling cards, without another envelope

A physical card carries only a non-secret URI:

```text
rappid://link/<percent-encoded-rappid>?m=<manifest-hash>&e=<endpoint>&n=<nonce>
```

The `.rappid-card.json` resource is still an exact eleven-key `rapp/1` frame. Its payload is the
closed card manifest, `m` is the existing payload particle, and `sig` is the existing detached
Ed25519 JWS. Verification is ordered and fail-closed: address, schema, key trust, expiry,
revocation, compatibility, policy, replay claim, hydration inventory, continuity, then `awake`.
The test profile is explicitly `rappid-card-test/1`; its visibly synthetic keys are refused in
production mode. See [`examples/05_rappid_card.py`](examples/05_rappid_card.py).
